日期：2026-10-10。基线：`smy19801388613-afk/yanxu-research-agent` 的 `31a4f36` 源码、项目既有验收记录和本地试用。本文不是投资建议、收益承诺或安全审计。本 PR 只实施第 5 节列明的基础护栏；其余内容是后续 PR 的设计依据。

## 1. 结论、证据等级与实际体验

产品宜定位为**可追溯、可追问、可复核的个人投研工作台**，而非自动交易或无人复核的目标价生成器。当前强项是财务事实、来源、估值假设和报告版本的分层；最需改进的是“找到材料”与“材料确实支持该结论”之间的验证、只读意图的可靠收束，以及研究任务的故障恢复。

证据标签：`实测` 是本次真实操作；`代码` 是源码可确认行为；`既有验收` 仅指仓库历史记录；`待验证` 是结构性风险或评测建议，不等于已发生故障。

## 2. 使用方法和能力边界

1. 在连接设置填写模型服务地址、协议、模型及密钥，并单独做真实连接测试。模型连接与 Tushare Token 是两条独立配置；不要把密钥放到聊天或报告中。此前密钥曾出现在聊天渠道，建议由持有人轮换。
2. 建立证券代码、财务年度和研究截止日明确的研究任务。没有 Tushare Token 时可选东方财富公开接口、匹配的披露文件或样例；实时研究意为当次请求供应商，不是实时股价。
3. 查看收入、归母净利润、经营现金流及同比和缺口。`api_only` 不等于核验；`verified` 仅表示接口与 PDF 金额匹配，二者可能来自同一份披露，并非两个独立信息源。负/零基期不得硬算同比。
4. 上传/查找年度 PDF 或按页阅读已接入材料。标题、搜索摘要、OCR 文字及“已读取 N 页”不等于原文全部经过核对；金额核查要保留期间、单位、口径和页码。
5. 在对话提出可证伪问题（例如现金流变化是否有营运资本附注支持），检查每步工具动作、已读正文与缺口。只读、勿联网或勿保存时明示约束，并核查动作记录。
6. 六种估值是**情景计算**；倍数、股本、FCFF、净债务等不得自行补零。方案先讨论并由用户确认，缺桥接项不推出股权或每股价值。不能把情景值称为当前市场价格。
7. 深度报告核对七章、论点反证、引用与版本；导出的报告或审计包不是来源独立性、全文阅读或投资结论正确性的证明。

## 3. 把论文方法融入现有研究链路

参考：周逸星《基于机器学习的事件信息量化分析与应用研究》，北京邮电大学硕士论文，2025 年。论文由用户以本地 PDF 提供，**原文件不随仓库分发**；下述页码均为该 PDF 的物理页（与印刷页可能相差约 11 页）。其主题是横截面选股预测，研序当前是单公司证据驱动投研。方法可借鉴，模型结果不可照搬。

| 论文方法 | 在研序中的改良用途 | 不直接移植的原因 |
|---|---|---|
 新闻事件抽取与按公司关联（PDF 第 30–39 页） | 在已读公告/网页/PDF 页中抽取事件主体、类型、对象、原句、出处，成为用户可纠正的事件候选；服务已有研究问题与反方材料查找 | 搜索摘要和情绪分数不能成为已核验财务事实；FinBERT 在中文财经语料上的适配要另测 |
 分析师首次覆盖、评级/目标价变化与时点区分（PDF 第 32–45 页） | 把有权限取得的研报组织成观点变化时间线，标明分析师、报告公开时点、目标价分母与证据链接；给出下一步追问 | Wind/Choice 等许可、授权和历史可见性未落实；龙虎榜营业部不等于分析师个人 |
 多通道融合和四类因子筛选（PDF 第 64–75 页） | 借鉴“分来源、设简单基线、做消融和分环境检验”的**评测纪律**：比较加事件层前后关键问题的可回答率、误引和人工纠错 | Rank IC/收益分组需完整股票截面和未来收益标签，不能评价单份研报；Mamba 不是第一期依赖 |

**同一条研究链路**：`Source → 原文 Evidence → EventRecord → Question/Claim → MemoRevision`。先验证事件的发生、主体和公开时点，再单独判断事件是否支持投资论点；“公司公布产品”不自动等于“产品形成利润”。继续把年报数字交给财务核验，把估值输入交给用户确认。相同事件的转载按原始来源聚合，更正和撤回保留为新证据，不能覆盖原件。

`EventRecord` 建议记录 `security_id`、`event_type`、`source_id`、原文定位、`occurred_at`、`published_at`、`first_observed_at`、`tradable_at`、`as_of`、实体、关联论点、提取版本、人工修正记录和去重关系。发生时间、对外公开时间、本系统首次获取时间及可交易时间不能混用；本系统今天发现的旧公告不能倒填“当年已发现”。`tradable_at` 仅在有可核查具体时刻及交易日历时计算，未知则为空。网页自称发布日期也要保留来源依据。

**论文自身的复现前置条件**：PDF 第 50 页称训练期约 2016-01 至 2022-03、测试期约 2022-03 至 2025-01，而第 75 页称“测试集”的牛市/震荡市段包含 2020–2021；需要确认是否是另外的跨期试验。第 50–51 页对分类标签写“过去 30 个交易日”收益，与未来预测任务的特征截点/标签窗口需重新对齐。第 77 页表 4-6 的 HME 总收益 869.23%、年化 28.52%，若是同一约 2.83 年区间，用几何年化无法互推；第 81 页明确未考虑交易成本和实盘风险控制。这些是待核对口径，不是经本项目复现的绩效。

未来若要研究因子：先取得合法且可按时点回放的历史新闻/研报/财务/行情数据，固定当时股票池、退市及 ST 状态，按公告和更正的实际可见时间入库；滚动时间训练/验证/留出，重叠窗口留间隔，所有标准化与特征选择只用训练数据；对照无事件、规则事件、简单模型和复杂网络，并计手续费、滑点、不可成交、换手、容量、行业与风格暴露。只有样本外多个窗口在成本后仍有稳定增量，才讨论展示预测性指标。该实验**不是**当前工作台优化的必做交付。

## 4. 目标架构、数据与调度

当前架构是 React → FastAPI → SQLite/本地文件，研究和 Agent 各由独立 Python 子进程执行，前端通过 SSE 轮询研究快照。研究与对话各最多两个活动任务；`BEGIN IMMEDIATE` 管并发，研究每步检查约 15 分钟预算，深度研究另有约 10 分钟边界，Agent 每轮最多 8 次模型决策。外部请求返回前取消可能延后。`代码：app/main.py、app/store.py、app/research.py、app/deep_research.py、app/agent.py`

演进原则是**先在单机拆契约，避免直接微服务化**：

| 边界 | 具体改法 |
|---|---|
 API/UI | 问题级状态显示：仅搜索线索、正文已读、事件已确认、论点已核查、有冲突或未回答。子页面标题位置、首屏节奏及窄屏/键盘操作保持一致。 |
 Planner/权限 | 工具可用性在模型决策前收窄，执行层再次校验；禁止动作后不消耗实际工具调用。失败时交付已有事实及未完成项，不假装完成研究。 |
 来源/事件/主张 | 来源保留原文、文件哈希、位置及时间依据；事件为有状态的候选，不与财务 `Fact` 混表；强断言必须有实际正文/可定位原句、期间和反证。 |
 财务/估值 | 扩展三表、附注、重述和 FCFF/净债务桥接；维持 `Decimal` 确定性计算。事件可触发“待复核”而不能直接改写财务事实或用户估值输入。 |
 Scheduler | `jobs`、`job_events`（任务进度）、`research_events`（研究对象事件）分表；幂等写入、租约/心跳、故障恢复和单调事件序号。仅压测证实瓶颈后迁出 SQLite。 |
 离线 Research Lab | 可选、资源隔离；训练/回测不挤占在线聊天和深度研究连接配额。无许可和可回放历史时不启用。 |

现有 `store.begin_turn` 扫描对话 JSON 统计活动量，SSE 推送大快照；对大量历史数据的影响尚未压测。逐步增加结构化状态与索引、增量事件和断线续传，迁移保持旧 JSON 可读；PDF/原始响应文件存储并按哈希去重，不塞进 SQLite 大对象。外部错误区分超时、429、HTTP 失败、JSON 非法和来源不可得；用任务 ID 关联时间、令牌量、费用与取消延迟，日志脱敏。

## 6. 阶段路线、验收与风险

1. **基线，约 1–2 周**：冻结此次两轮对话与 30–50 条权限/日期/引用用例；补公告缺日期、转载、更正、同名公司与截止日后信息的标注样本。先给误引率、事件主体/时间错误率测基线；本文时长只是估算。
2. **证据和事件最小契约，约 2–4 周**：只从可定位正文提候选事件，按原句和时点展示问题缺口；历史截止日不使用晚于截止日公告。对人工标注集逐项核对抽取、日期依据和反证，确定上线阈值。
3. **可靠任务和事件融入研究，约 3–6 周**：将事件候选加入读正文与写报告之间，补租约、幂等、增量 SSE 和错误分类；以相同问题、截止日和检索预算比较“原链路/加事件层”，关键问题可回答率提升且误引不得升高；崩溃后有可见终态。
4. **金融底座和持续跟踪，约 6–12 周及长期**：在 10–20 家人工核对公司中覆盖亏损、重述、负 FCFF、金融/非金融口径；更正发生时旧论点进入待复核而非静默改写估值。只有数据许可、历史可回放和可靠性达标，再决定是否启动独立因子实验。

周度面板：关键问题可回答率、引用原句可定位率/误引率、事件主体和公开时间准确率、更正与反证发现率、误把单源当双源次数、越权工具尝试/成功次数、任务恢复率、P50/P95 延迟、取消延迟、每轮令牌和估计成本。分样例/模拟服务/真实公开来源/真实模型统计；不得把演示样本的效果与真实运营混报。

风险与待验证项：本次笼统模型错误的真正类别未知；SQLite 大快照的瓶颈和进程崩溃是否占用名额尚未压测；供应商历史修订、公告遗漏和 OCR 误识别尚需人工样本；本机 DPAPI 只保护静态密钥，上传 PDF 与对话可能外发所选模型；公网部署另需认证、授权、CSRF、速率限制和备份。新闻/研报/Wind/Choice 的使用和训练许可须先确认，不照搬论文中的爬虫或验证码绕过方案。

项目内参考：[使用说明](../README.md)、[v0.2 架构](architecture-v0.2.md)、[v0.3 研究审计](reference-review-v0.3.md)、[既有验收](acceptance-v0.3.0.md)、[买方评审](buy-side-review/acceptance.md)。目标不是生成更长报告，而是少做越权动作、更准确地说明哪些证据支持结论、哪些问题仍缺答案。
