# v0.5.2 基础机制与备忘录版式验收

本轮修复执行授权、财务口径、报告依赖和停止后续接的已确认问题，同时优化备忘录页面及 HTML 导出。历史研究不迁移，不自动重写原报告。

## 修复与验证

| 场景 | 修复后的行为 | 验证方式 |
| --- | --- | --- |
| “确认方案中的股本单位” | 仅核对，不视为采用方案 | 临时 SQLite 中走真实 begin_turn、合同、工具校验与保存链 |
| “不要用 PE20，采用 PE15” | 完整语句约束参数；截取“PE20”不能作为授权 | 新旧参数、条件句、否定句、采用旧方案同时改参数的回归 |
| “保存财务期间底稿” | 单独完成底稿交付，不额外要求完整报告 | 固定模型响应驱动真实 agent.execute，检查终态和原报告未变 |
| 年度事实与期间记录不一致 | 同口径金额真正冲突时阻断相关估值、期间计算及派生引用 | PE/PS、敏感性、旧估值入口、同比引用和报告保存校验 |
| 年报取整与 API 小数值 | 按原始单位和披露精度判断兼容，保留所有原值与核验状态 | 千元、万元、亿元、原始小数、边界和超限；禁止粗精度第三条记录掩盖两条精确数据冲突 |
| 已保存估值与冲突数据 | 即使情景版本相同，也标记依据不可用；不影响无关指标/年度 | 保存、制造冲突、撤去错误记录并恢复的完整链 |
| 跟踪基线的独有来源变化 | 标记报告待同步；生成期间变化则拒绝旧稿覆盖 | 实际报告构建/修订与并发变更测试 |
| 局部改标题后待处理观察 | 待研究观察继续保留，并进入后续模型上下文 | 跨报告版本、超过单次输入上限、生成期间新增观察测试 |
| 同一 PDF 来源扩读后修订正文 | 新正文使用当前来源，旧建议保留独立的冻结来源 | 同编号来源新旧摘录分别保存、UI 和导出展示断言 |
| 独立研究取消/超时后新对话继续 | 新执行使用新预算；旧执行、取消标记和预算历史保留，旧进程无写权限 | build/refine 实际保存链、预算记账和旧 worker 写入拒绝 |
| 概览状态连接中断 | 自动获取状态并重连到终态，切换研究后的迟到响应被忽略 | 6 个实际 JavaScript 异步恢复场景 |

原始精度兼容只说明数值允许的舍入范围，不能证明来源真实或独立。年度兼容记录按更高原始精度计算并显式记录选择规则；不会自动把原文单源升级为已交叉核验。

## 报告设计

- 保留紫荆紫，采用白色纸面、清晰字级与统一留白。
- 投资建议优先显示未持仓、已有持仓动作；行情与用户估值情景分栏，保留日期、币种与假设说明。
- 正文按编号导航，论点与反证分层；来源标题可收敛显示，但 PDF 页码保持可见，完整标题与摘录仍可查阅。
- 待处理观察和失效依据有显式提示。历史建议不因局部排版或文字修改而被刷新。
- HTML 使用独立样式，无外部字体或脚本依赖；支持正文表格、A4 打印、重复表头和完整证据附录。主要行情、估值和涨跌空间展示为两位小数，原始精度仍保留在提示、情景明细和 JSON 中。普通版减少内部状态字段，审计版保留原计算并加失效说明。

## 验收范围

机制回归使用临时数据目录与固定模型响应，执行真实的权限、合同、计算、存储和保存路径，不消耗付费模型额度。伊利股份第 6 版、中芯国际第 5 版用于检查真实历史报告的显示及 HTML、Markdown、JSON、证据包读取；这不是重新联网生成两份新投资结论。

旧报告缺少观察输入记录时，观察保守显示为待处理；整稿记录“已提供给模型”也不等于独立核验或问题已解决。缺少冻结来源时显示缺口，不使用新来源冒充历史依据。
