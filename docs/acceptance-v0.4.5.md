# v0.4.5 累计 Token 预算与重复读页修复

日期：2026-10-15。

## 诊断证据

只读检查本机紫金矿业最新对话：北京时间 18:19:42 开始、18:22:46 结束。旧版配置为 65,536 单次生成 tokens、30 分钟、32 次模型决策。本轮实际 32 次模型调用、31 条 read_document 步骤，参数只有 4 种；其中第 120 页被请求 28 次，27 次属于缓存复用。每次复用仍把完整结果再次加入模型上下文。

服务商 usage 累计 4,546,543 tokens，其中输入 4,542,249，输出 4,294。旧版决策额度统计的是模型选择动作，一次 read_document 可读 1–3 页，并非固定每个物理页计一次；这次同时存在决策上限、同页循环和重复输入膨胀。

## 实现

- 删除总决策次数上限及最后一次强制回答逻辑。默认改为每轮累计 1,000,000 tokens、15 分钟；滑动范围分别为 50,000–5,000,000 tokens 和 1–60 分钟。
- 主循环、深度报告内部调用、截断重试共享账本。请求前预留保守输入估算和输出上限，服务商返回 usage 后结算；输出按剩余额度缩小，不足下一次请求时停止。服务商已经包含的缓存和推理 tokens 不重复累加。
- 缺失 usage、网络失败、取消、超时或异常终态，将无法确认部分明确记为保守估算；旧 worker 无权覆盖新轮账本。用量组件分开呈现接口报告、估算和请求中预留。
- 两个滑动条可保存默认值，运行中冻结。旧三字段预算保留时间并采用新的累计默认值，旧单次生成额度不等于整轮额度；旧历史不改写。
- 相同成功工具结果仅保留一份观察；再次查阅旧页时将该结果移到最新，重新提供完整原文，避免旧页被摘要后永远无法读到尾部。三个连续相同缓存或无效动作触发停滞提示，正常换页和不同缓存页对照允许继续。
- 决策上下文移除旧报告长正文、问题修订历史和重复结果，保留最新阅读全部页的工具原文、最新用户意图、全部当前问题、来源状态、URL/ID/页码及产物状态。常规约 35,000 字符为软目标；原文和定位信息优先保留，由累计 token 准入约束。原数据库内容不变。

真实任务的重建输入从约 284,136 字符降到 33,612 字符，31 条工具观察归并为 4 条，11 个当前研究问题全部保留。该结果是本地输入重建比较，不是新一轮真实模型效果或账单验证。

## 验证

使用临时数据库及模型 stub，未发起真实付费模型研究。回归包括超过 32 次决策、连续 35 个不同 PDF 页、同页循环、缓存旧页全文恢复、不同缓存页对照、内部调用与重试累加、预算不足的提前拒绝、取消/超时结算、旧配置迁移及旧 worker 写入隔离。

全量 Python 回归：527 passed、1 skipped（Windows 符号链接权限）；TypeScript 检查、Vite 生产构建和 `git diff --check` 通过。审计账本保留数值用量，密钥与未知 token 字段继续脱敏。

浏览器在隔离 SQLite 快照验收两个滑动条、150 万 tokens / 30 分钟保存和刷新、已报告/估算用量显示。1440×960 桌面和 390×844 窄屏无横向溢出，控制台无错误。样例用量为人工验收数据，不进入正式研究。

## 边界

累计 tokens 不是人民币费用；服务商计费规则、缓存价格和缺失 usage 都可能影响账单。输入预留使用 UTF-8 字节数加封装余量进行保守估算，因此可能在仍有少量额度时拒绝下一次请求。单次输出仍受模型协议和服务商限制。停滞保护不保证模型不会绕换无效动作；累计 tokens 与时间继续兜底。

原文完整保留指当前工具返回文本；PDF 工具原有每页 16,000 字上限、OCR 识别质量、日期与证据资格限制仍适用。本次未替用户执行新的正式研究、修改问题答案或改写报告。
