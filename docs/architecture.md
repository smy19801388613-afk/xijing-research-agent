# 当前架构与能力边界

析鲸AI使用模型决定下一步、受限工具实际执行、工具结果进入下一轮的循环。普通对话不要求每次执行固定流程。后端为 FastAPI/SQLite，前端为 React/TypeScript；后台进程与浏览器请求分离，SSE 展示实际执行。

数据流：公开/上传材料 → 财务事实与来源 → Decimal 计算 → 问题与证据 → 估值情景与研究报告 → 当前稿/审计稿/证据包。

| 层 | 模块 | 责任 |
|---|---|---|
| 原始材料 | documents、ocr、disclosures、public_pdf、web_research | 检索、阅读、页码、日期和来源状态 |
| 事实与计算 | research、finance、valuation | 期间/单位、来源冲突、确定性计算、假设隔离 |
| 研究执行 | agent、deep_research、turn_constraints | 有界决策、用户限制、证据读取、反方审阅 |
| 保存与交付 | store、report_state、exporting、main | 原子版本、报告与估值关联、导出/API |
| 交互 | AgentChat、MemoView、ValuationLab | 研究对话、原文定位、情景与报告 |

当前自动结构化范围是两年年度营业收入、归母净利润与经营现金流；六种估值不等于六种自动完整建模。DCF 为恒定增速加永续终值，FCFF、桥接等尚需输入。引用校验不等于自然语言主张全部正确。

v0.4.0已实施受控比赛模式（competition）、派生事实状态（fact_state）和问题级证据清单（questions）。新字段兼容旧历史；旧材料与报告不自动覆盖。历史设计见 [v0.2](architecture-v0.2.md)，历史实测见 [v0.3.1验收](buy-side-review/acceptance.md)。


## v0.4.8 执行与保存约定

- `task_contract` 解析当前有效目标、权限、交付条件和续接范围。历史任务轮次用于追溯，当前义务轮次用于执行与交付。规划、工具入口、来源阅读和界面覆盖统计读取同一合同；旧记录只读适配。
- `report_state.report_identity` 用版本号与正文指纹标识发布稿。生成开始时冻结基准，保存事务先比较基准，再更新问题记录、归档旧稿并发布。修复草稿时刷新证据也不能改变原始发布基准。
- `dependency_snapshot` 统一报告同步和缓存依赖：问题/绑定证据、实际引用来源、研究日期、财务事实/计算和当前语义估值情景。仅新增无关未引用资料不导致失效；等价估值的不同 ID 不等于新情景。缓存另核对发布稿身份，不能以另一对话的旧版本交付。
- `report_edit` 从真实用户轮次取得可修改字段；模型只输出字段补丁，程序合并原稿后全量校验。未授权正文原样保留。`review_state` 保留稳定审阅意见及待复核状态，编辑成功不等于独立复审通过。
- `execution_budget` 在独立研究和聊天内研究共用累计 Token 账本及时间截止；内联调用继承外层额度，不新增总决策次数限制。并行检索线程继承执行上下文，取消栅栏不会因线程切换失效。
- `runtime` 保存启动意图，登记 PID 和创建时间，启动失败回写终态；服务启动及周期检查确认退出的活动任务，保留未知进程和启动宽限期。研究与聊天共享并发名额，内联研究不重复占位。
- `store` 的业务快照使用乐观并发版本，拒绝旧快照覆盖；预算回执独立原子更新，业务保存合并最新用量。取消先撤销写权限，再结束已验证身份的工作进程。

这些约定减少状态冲突，不保证所有自然语言请求都能无歧义解析，也不等于模型结论经过金融专家复核。旧报告的依赖关联不足时显示未知，下一次明确修订才建立新关联；不批量改写历史。
