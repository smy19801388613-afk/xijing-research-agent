## 已实施

| 原问题 | 当前机制 | 关键验证 |
|---|---|---|
| 继续对话同时受原始任务和当前限制驱动 | 版本化任务合同作为当前范围、权限、交付的共同来源；原任务仍保留用于追溯 | 完整深研改为只解释/定点修订后能完成；继续不会恢复旧义务；历史轮次读取不受未来偏好影响 |
| 两个对话先后覆盖同一报告；缓存返回过期稿 | 生成时冻结报告版本及正文指纹，事务内比较再保存；缓存同时核对依赖和发布稿身份 | 两线程并发保存恰有一个成功；修复阶段刷新证据也不重新绑定旧稿基准；另一对话新稿保持原样 |
| 同步提示和缓存对依赖的理解不同 | 共用语义依赖快照，追踪问题/绑定来源、引用来源、财务输入和估值情景 | 无关新闻不会失效；引用/事实/计算/问题/情景变化会失效；等价数值格式和重复情景 ID 不会造成误判 |
| 局部修改仍重写整份报告 | 从真实用户请求确定可修改字段，模型提交字段补丁，程序合并并校验 | 章节/摘要/标题/论点编辑保留其他字段；模型换报告工具无法绕过；范围不明确时阻止整稿替换 |
| 独立研究与聊天预算不一致，孤儿任务挂起，旧快照覆盖 | 统一累计 Token/时间账本，内联继承；启动补偿、身份核对、定期恢复、业务版本保护 | 本机 HTTP 两次真实模型协议调用完成并保留账本；连续流超时退出；启动/登记失败、进程死亡、启动竞争与旧快照冲突得到处理 |
| 修订后反方意见被清空 | 稳定意见 ID，保留内容和前状态；未复核不自动标记解决 | 定点修订、直接修订、完整重研及工作草稿合并均保留旧意见；页面与导出兼容旧字符串和新结构 |

并行检索继承执行上下文：真实搜索线程池共享同一预算；深研阅读线程在取消后写库触发执行栅栏，迟到文档不落库。总决策次数继续不设上限，重复无进展保护仍保留。
